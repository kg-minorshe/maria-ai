# Текущее состояние системы

## Конфигурация
- **Бэкенд/фреймворк:** Node.js сервис на Express с модульной цепочкой (контекст-менеджер, анализ запроса, семантический поиск, генерация ответа, моделирование пользователя, эмоциональный слой и движок рассуждений).【F:src/app.js†L1-L120】
- **Архитектура диалога:** Хранение истории по сессии с окном до 25 взаимодействий и тайм-аутом контекста 45 минут; эмоциональные состояния фиксируются для каждой сессии.【F:src/modules/dialog/DialogContextManager.js†L1-L79】
- **Токенизация/нормализация поиска:** Текст приводится к нижнему регистру, очищается от неалфавитных символов, разбивается на токены длиннее 2 символов, удаляются стоп-слова и применяется стемминг для русского языка; поддерживаются синонимы и n-граммы.【F:src/modules/search/SemanticSearchEngine.js†L530-L565】
- **Контекстное окно:** Текущее окно диалога — до 25 сообщений, сессии очищаются по таймеру; контекст резолвит сущности, темы и поток диалога на основе последних ходов.【F:src/modules/dialog/DialogContextManager.js†L1-L120】
- **База знаний:** Загружается из `data/knowledge/knowledge-base-project.json` и `data/knowledge/knowledge-base-general.json` и обогащается метаданными при старте сервиса.【F:src/services/knowledgeBase.js†L4-L110】

## Метрики
- **Benchmark:** `knowledge_base_alias_top1` (top-1 accuracy по первым 20 элементам базы знаний, запросы — первые алиасы/заголовки; добавлены 12 стресс-кейсов без эталона).
- **Результат:** accuracy = 1.0 (20/20 попаданий).【F:reports/benchmark_metrics.json†L1-L7】
- **Методика:** Node.js-скрипт `scripts/run_benchmark.js` использует `SemanticSearchEngine` для вычисления top-1 accuracy по тестовому датасету и сохраняет метрики и неудачные кейсы для регрессии.【F:scripts/run_benchmark.js†L1-L93】

## Известные неудачные кейсы (для регрессии)
- 12 собранных примеров из стрессовых запросов (подписки, платежи, поддержка, аккаунт, настройки и пр.), где система либо возвращает нерелевантные статьи, либо не находит ответ.【F:data/eval/failure_cases.json†L1-L120】
- Файлы `reports/benchmark_metrics.json` и `data/eval/failure_cases.json` можно использовать для автоматизированных проверок после изменений.
