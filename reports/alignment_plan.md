# План выравнивания модели и безопасности

## Датасет инструкций
- **Формат:** `data/alignment/instruction_dataset.json` (версия 1) с явными полями: `language`, `domain`, `input`, `context`, `expected_output`, `output_type`, `safety_tag`.
- **Покрытие доменов:** финтех/подписки, поддержка, продукт, ETL, ML-оценка, triage, DevOps, UI/локализация, приватность, red team, prompt injection, retrieval grounding.
- **Билингвальность:** примеры на русском и английском; каждый пример содержит ожидаемый стиль/выход для обучения/валидации генерации.
- **Безопасность:** помечены кейсы `reject` (фишинг, малварь, prompt injection, запрос логинов, вредоносные инструкции) с явным ожидаемым отказом.

## Контент-фильтры и отказоустойчивость
- **Классификатор безопасности:** `data/alignment/safety_classifier.json` содержит примеры с метками `allow/reject` и рационалями для обучения/калибровки (линия раздела: вредоносный софт, фишинг, приватность, self-harm, дезинформация, prompt injection).
- **Инференс-пайплайн:**
  1. Прогнать запрос через safety-классификатор; если `reject`, отвечать шаблоном отказа и журналировать метку.
  2. Для `allow` — подбирать релевантную инструкцию из `instruction_dataset` (по домену/языку) и генерировать ответ в требуемом `output_type`.
  3. Для смешанных запросов применять **rejection sampling**: при подозрении на вредоносный контекст перегенерировать до 3 раз, затем вернуть отказ.
- **Примеры безопасных ответов:** кейсы triage, приватность, политика, а также red-team запросы с отказом и предложением безопасных альтернатив.

## DPO/RLHF на предпочтениях
- **Пары предпочтений:** `data/alignment/preference_pairs.json` — prompts с выбранными/отклонёнными ответами (grounding, приватность, jailbreak denial, медиц. отказ, краткость). Использовать для DPO или классического RLHF (PPO + KL) для усиления предпочтений.
- **Сигналы качества:** краткость, фактическая обоснованность, соответствие политике безопасности, корректный тон.
- **Отбор батчей:** смешать домены и языки, oversample редких `reject` кейсов, включить 20–30% трудных примеров (prompt injection, социальная инженерия).

## Валидация и красные команды
- **Регрессия:** пополнить стресс-кейсы из `data/eval/failure_cases.json` и добавить новые jailbreak/prompt-injection запросы; фиксировать top-1 попадание и долю корректных отказов.
- **Red team:** еженедельно прогонять набор инъекций (рус/англ), попытки обхода отказов и социального инжиниринга; метрика — recall блокировок и отсутствие утечек.
- **Мониторинг продакшена:** логировать срабатывания safety-фильтра, долю отказов, количество повторных генераций при rejection sampling.

## Быстрый старт
1. Обучить safety-классификатор на `data/alignment/safety_classifier.json` (+доп. внутренние данные), интегрировать как pre-check.
2. Тонко настроить генеративную модель с инструкциями из `instruction_dataset.json`.
3. Запустить DPO/RLHF на `preference_pairs.json` для усиления отказов/grounding.
4. Прогнать regression + red-team сценарии; документировать метрики и обновлять наборы каждые 2 недели.
